# AI 可制作契约

只有“明确描述、可配置数据、资源映射、可执行验收”相互对应，才具备制作条件。本文是目标实现的**检查清单**，不是要求建立九套专业文档；同一执行者继续制作时，一个 `production-spec.md` 加 `coverage.csv`/资源 manifest 即可。每个系统用 ID 串联来源证据、目标决策、目标数据、资源和实现位置。研究事实不能替代目标取值；原作未知不一定阻塞已知系统的实现，但严格复刻中不得把推断写成已证实事实。

## 各专业必须可回答的问题

| 专业 ID | 必须落地的信息 |
| --- | --- |
| gameplay | 核心循环、玩家输入与意图、初始状态、状态转换/优先级、实体生命周期、碰撞/命中/交互规则、胜败与重试、暂停与存档；时间制/回合制、随机种子和异常分支 |
| levels | 线性关卡/章节的地图尺寸、坐标轴/单位、图层、碰撞和移动、相机、出生点、交互点、触发条件/效果/次数、出口与目标、遭遇/刷怪、路径和软锁检查；逐关内容及节奏目标。开放世界只定义核心任务/玩法所需的最小可玩区域，不要求全量大地图地形 |
| balance | 字段名/类型/单位、初始值/范围、公式和运算顺序、取整/上限、实例覆盖、消耗与产出、成长与难度、掉落与随机；至少给能手算的输入输出样例 |
| ui | 页面流、组件语义、显示字段、触发命令、可用/禁用/空/错误状态、键鼠/触屏/焦点、文案与无障碍；不要求像素级布局、皮肤、配色、字体或装饰一致 |
| audio | 原作事件→原版音频文件路径/ID、来源与许可、触发/冷却/并发、循环/停止、音量、静音/设置；忠实逆向必须使用原版 SFX/BGM/环境音/语音，不创建替换工单或候选，缺失项标 `unresolved-original-audio` |
| vfx | 事件/语义/锚点、预备/发生/消退时序、与命中/状态/提示的关系、镜头震动/停顿、性能与池化；只实现简单可辨反馈，不逆向 Shader、复杂材质/光照、后处理或粒子渲染，不得用视觉效果代替规则判定 |
| asset-slots | 最低可玩资源映射：原资源 ID→语义槽位→runtime 资源路径；每个关键角色/敌人/NPC/物件有可辨认的模型、图片或占位形体，场景可导航并能辨认交互区域；只记录必要格式/尺寸/帧数/pivot/anchor/碰撞/占地/挂点。禁止复刻原作美术或 Shader，不要求完整开放世界地图 |
| narrative | 世界观/人物、文本 ID、分支条件和跳转、演出顺序、对白/选项与超时、解锁/结局、本地化；无叙事时标 N/A 并说明 |
| engineering | **默认目标底座为 `HGame` 引擎（`hgame-spec-forge` + `scripts/re-pipeline.mjs`）**；记录渲染 profile（`2d`/`3d`/`ui`）、`engine.config.json` 模块清单、净室规格映射（`clean-spec.json`）、版本化存档与性能预算，淘汰手搓野生单 HTML 主循环 |

按游戏实际需要检查这些专业问题；不适用的内容在总账本中标 `not-applicable` 并简述理由，不创建空章节或空文件。存在必需但未设计项时记录为 `missing/blocked`，继续其他不受影响的工作流。不能为使检查变绿将用户明确要求的专业标 N/A。

## 制作包的三个完成条件

1. **自足**：执行者不需要原游戏和聊天历史即可理解并实现当前 slice。关键文档、目标数据与引用存在；不得使用“同原作”“其余类似”“自行发挥”替代必需定义。敏感原始输入不必分发，但影响实现的知识必须落在制作包。
2. **闭合**：可从固定初始化状态按步骤走到阶段完成/胜败并重试。地图/任务触发、公式、UI 交互、原版音频、简单特效反馈都有状态事件连接；玩家、敌人和关键对象可辨认，场景能导航和交互。允许使用低模/Sprite/灰盒/占位图完成可玩表现，不要求最终美术、原作画面或完整开放世界地图。
3. **可验收**：每个关键规则有前置/动作/预期状态，至少覆盖启动、主循环、结束/重试、存档（如适用）、输入与画幅、声音、资源失败和生产预览。自动化检查与人工手感/试听/用户验收分开。

packet `ready` 仅表示上述内容经人工冷读完整；用户批准在 `approval` 中单独记录。没有批准不得冒称 approved。`ready` 加 `approval=pending` 仍是可审阅的完整包，执行 AI 应遵守批准边界。

## AI 交接冷读（仅独立交接时）

同一执行者连续逆向与实现时不重复冷读每个系统。只有 packet 将交给另一个独立执行者时，才只读完整制作包做一次最终冷读：

只给制作包，不给原游戏或原对话，要求执行者返回：

- 将用哪个 starter profile、首批实现哪些文件与系统、哪些属于后续完整目标？
- 从默认值开始列出一次完整操作、所有状态与数值变化、终止与重试结果。
- 指出必须猜测的控制、时间、公式、地图、资源与交互；分别给包内定位，缺少则报告，不擅自补成“原作事实”。
- 说明各资源来自哪、如何获得、缺口如何处理；原版音频哪些尚未定位、映射或通过解码验证？
- 给出程序/规则/构建/浏览器生产预览和原版音频映射/播放验证计划；视觉只检查对象可辨、场景可导航、基本反馈可见，不做原作美术对照。

若关键项仍需猜测，修包再读。若只是原作未知而目标已经明确，不阻止实现。没有目标项目时不伪造它的 package scripts；先按 starter 的实际 README 写创建命令，创建后再读取 package.json 确定验证命令。
