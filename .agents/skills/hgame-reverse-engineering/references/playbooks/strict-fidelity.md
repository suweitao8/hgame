# 严格复刻模式（程序、策划与音频）

用于用户要求一比一或完整一致的场景。默认分析对象是用户指定构建；先记录文件快照、平台、语言、画幅、设置、进度和输入条件。HTML 指网页技术交付，不默认要求全部代码和二进制塞进一个 HTML 文件。

**严格复刻的边界是约定的离线单机程序、完整策划内容与原版音频**：单机玩法、剧情、线性关卡、任务/分支、规则、数值、AI、UI 交互、原版 SFX/BGM/环境音/语音、进度和本地存档要求忠实；原版音频文件必须直接使用，不得用公共库、合成音或 AI 候选替换。视觉美术只需达到最低可玩表现（可辨认的模型/图片/占位形体、可导航场景和基本状态反馈），不要求原作画风、造型、材质、灯光、纹理、模型细节、粒子外观、UI 皮肤或像素级布局。开放世界不要求还原完整大地图和全部地形探索点，只搭建核心任务/剧情节点和玩法所需的最小可玩区域；线性关卡/章节地图仍需完整还原。登录、认证、多人匹配、排行榜、云存档、支付、广告、遥测与反作弊等网络/平台专属部分明确标为 `excluded-online`，不作为逆向或完工验收项目。若单机功能必须依赖原服务端，研究其可观察玩法规则并转换为纯本地实现，记录平台适配差异。此排除规则不是允许减少单机章节、任务、分支或游戏系统。

## 关键区别

- 程序、策划、内容和原版音频中的 unknown 继续作为研究问题。不得用原创规则、常见同类机制、其他版本攻略或替换音效补齐后宣称一致。视觉素材可使用现成模型/图片、低模、Sprite 或占位形体；外观差异不列 fidelity deviation，但必须满足可辨认、可导航、可操作和基本反馈要求。
- 实现方法可以不同，例如浏览器存档适配、资源预加载和模块结构；必须保持已约定的外部可观察行为。无法保持的平台功能明确列差异，不自行省略。
- UI 保留页面流程、信息字段、控件语义、输入、状态与命令；不要求像素级排版、颜色、字体、装饰或皮肤。VFX 保留事件语义、触发和玩法相关时序，外观可以重做。
- 视觉素材只记录程序接入所需的 `source_asset_id → semantic_slot → runtime_asset_path` 和必要的格式、尺寸、帧数、pivot/anchor、碰撞/占地/挂点；优先复用现成模型/图片，缺少时用简单替代物，不做逐图/逐模型外观研究，不逆向 Shader、材质/灯光/纹理/造型。
- 线性关卡和章节地图的玩法数据必须完整；开放世界整张地图不纳入逆向范围，只构建支撑主要任务、剧情节点和核心系统的最小可玩区域。不得把开放世界地图范围缩减扩大为删除任务、剧情、数值或角色系统。
- 小切片只用于一次性校准新的解析/数据映射方法；不要为每个系统重复制作和测试小切片。全量范围持续登记，不能以切片成功替代全游戏完成。对已经有充分证据的部分可以开始忠实实现，无需等待所有原作未知消除才做任何工作；功能对照统一进入第二阶段。
- 文档可制作、代码可运行、对照测试通过、完整覆盖和用户验收分别记录。现有校验器只检查结构和声明，不能证明严格复刻；不要仅改 covered/ready 使它变绿。

## 最小证据资料

不要把下面六项机械地拆成六份文档；按实际复杂度合并，避免重复记录：

1. **baseline**：每个游戏一次，记录构建 hash、运行条件、初始状态和输入范围。
2. **coverage.csv**：唯一总账本，逐系统/内容集合/资源批次记录 ID、来源、实现位置、逆向状态、实现状态和验证状态。不要逐个重复登记可由自动 manifest 完整列出的普通文件。
3. **rules/timing**：只有复杂公式、状态机、事件优先级、随机消费顺序或时序确实需要展开时才建立专题文档。
4. **asset dependencies**：仅当程序/策划/音频引用需要跨包追踪时建立依赖图（如 prefab→碰撞/玩法数据/音频事件/语义素材槽位）；不为完整图片/字体/模型美术库建立依赖图。简单项目直接使用槽位 manifest。64 位 ID 不得经 JavaScript `Number` 丢失精度。
5. **comparison plan**：第二阶段开始时再建立，记录原作输入、程序/策划/音频基准、设备条件和误差标准；不建立原作美术效果对照基准。
6. **deviations**：只记录程序、策划、原版音频或平台差异；视觉简化/替换和完整开放世界地图不在范围内，不记录为 fidelity deviation。原版音频缺失必须明确记录，不能用近似音频关闭缺口。只有存在未证实、缺失或平台差异时才创建；无差异时不创建空表。未知项直接留在 coverage ledger 中。

原作源文件不必全部交给执行 AI；影响实现的知识和合法可用资源必须自足。正式交接时引用这些权威资料，不再复制一份内容相同的交接说明。

## 原作实验

原作实机实验和原作/Web 结果对照属于第二阶段；第一阶段先整理已有源码、数据、录屏和可重复实验方案，不逐项启动原作/复刻版测试。进入第二阶段后，针对具体未知设计可重复操作：固定初始进度、输入、速度/暂停设置和环境；记录帧率、镜头、计时误差及结果。能取得随机种子/算法则固定并对照轨迹，不能控制时分开检查确定规则和统计分布。不要把有限实验夸大为所有状态已证明等价。

对规则和音频计时，记录首发、后续间隔、触发延迟、停止/打断以及特殊状态。动画仅在影响命中、碰撞、无敌帧、移动或状态提示时记录必要时序；不分析逐帧画法。配置值、实例覆盖、代码使用点和运行观测交叉验证；发现冲突则保持未解决，不选看起来顺眼的结果。

## 资源与本地规范冲突

视觉简化是本工作区明确的产品选择，但最低可玩性仍须通过；不对照原作画面。音频必须使用原作文件，第二阶段验证来源映射、解码、事件触发和播放参数，不进行替换音效 A/B。记录原资源使用条件，不把拥有游戏当作公开发行授权；原作音频仅能在项目明确允许的本地研究/原型范围内使用，公开再分发前另行核验许可。

## 持续执行

研究结束的交付是已解问题、未解问题、证据和下一步任务，而不是整个复刻已完成。用户要求继续补齐时，优先执行仍可安全开展的提取、引用关联、原生静态分析、对照实验准备和已获批准的实现；不要反复输出同一份缺口清单。仅在真正需要用户输入/权限或环境条件时明确指出具体阻塞，不把工作量大当成阻塞。
