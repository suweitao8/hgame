# Engine gaps found while building the reference examples

Found while building and verifying `examples/survivor-2d` (2D, webgl2d) and `examples/arena-3d` (3D, three + spring arm + adaptive quality).
Status: **open** unless marked DONE. Nothing here blocks the examples; each item names the workaround used.

| # | Area | Gap | Workaround in examples | Suggested fix |
|---|---|---|---|---|
| 1 DONE | `scripts/create-game.mjs` (`--bare` added) | The 3D profile always scaffolds demo content (`level.json`, `materials.json`, `model-slots.json`, a Chinese-language `README.md`/`AGENTS.md`, an index.html title). A game that does not use the modular-level pipeline has to delete them by hand. | `arena-3d` deletes the demo files and rewrites `main.js`/`index.html`. | `--bare` (or `--template empty`) flag that emits only configs, an empty `main.js`, and the vendored runtime. |
| 2 DONE | `scripts/package-game.mjs` (WASM only when physics is used; `physics.bundleWasm` override) | `physics3d` pulls the Rapier WASM into every package (arena-3d: 6.5 MB output, 1.9 MB zip) even when gameplay runs in a pure sim and never touches `scene.physics`. | Kept `physics3d` because the example brief requires it; the sim is deliberately engine-free so it is testable headlessly. | Document that the feature is opt-in cost; optionally lazy-load the WASM on first `scene.physics.add`. |
| 3 DONE | Headless testing (`createSeededRng`, `hashState`, `runScripted`) | There is no engine-provided deterministic fixed-step harness for gameplay sims: each example hand-rolls a seeded RNG (`mulberry32`), an FNV hasher and a scripted-input driver (`src/sim/rng.js`, `script.js`). | Copied per example. | Export `createRng` + `createStateHasher` from `index.js` and a `runScripted(sim, input, ticks)` helper (would also serve `lockstep/`). |
| 4 DONE | `scripts/snapshot.mjs` (`--eval`, `--freeze-time`, `--steps`, state hook) | Cannot read game state from the page (`--eval <expr>` / `--dump window.__x`), so tests cannot assert "enemy count > 0" in the browser, only pixels. HUD text with an `fps` readout makes baselines flaky; survivor-2d output is not byte-identical across two runs because it is wall-clock driven. | `arena-3d` baseline is committed (two runs were identical); survivor-2d has none. | `--eval` to print a JSON expression, and a documented `?freeze=<ticks>` convention for deterministic snapshots. |
| 5 | Snapshot baselines | Baselines are per environment (SwiftShader/Chrome build); CI on Linux can differ from the committed Windows PNG. | CI uses `--threshold 0.1`. | Generate baselines in CI and cache them as an artifact rather than committing. |
| 6 DONE | `camera3d` (`createSpringArmRayProbe` added; box helper still open) | `createSpringArm3D` `collisionTest` accepts a number, `{distance}`, `{toi}` or `{fraction}`, but the JSDoc does not list the callback arguments `(pivot, desiredPos, backVec, length, radius)`; I read them from source. | `rayBoxes` in `examples/arena-3d/src/sim/collide.js`. | Document the signature and ship a `createBoxCollisionTest(boxes)` helper. |
| 7 | `three` adapter | The three adapter exposes `setSunLight` but no helper to fit the shadow frustum to the quality tier's `shadowDistance`; examples hard-code `shadow.camera` bounds. | Hard-coded 44x44 ortho box. | `renderer.fitShadowToPreset(sun, target)`. |
| 8 DONE | Input (`cameraRelativeMove` in camera3d) | `app.input.isDown()` returns a boolean, but every call site does `Number(a) - Number(b)` arithmetic by hand; `createArcadeControls` has `getMove` for sticks but no camera-relative variant for third-person games. | Manual rotation by `arm.yaw` in `Driver.fixedUpdate`. | `p1.getMove(out, { yaw })` or `getMoveRelative(yaw)`. |
| 9 | Example tooling | `vendor/` is generated and git-ignored, so a fresh clone needs `npm run build:examples` before the examples run in a browser or package. | `tests/examples.test.mjs` auto-builds when missing; CI runs `build-examples.mjs` first. | none needed; documented in the README of each example. |

No runtime bugs were found that were small and safe enough to patch in `assets/runtime` in this pass; the items above are API/tooling ergonomics. No runtime files were changed, so there is no CHANGELOG entry for the runtime.
