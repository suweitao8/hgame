# HGame 工程就绪评估 · 2026-11-17

按“AI Agent 开发自包含 2D、3D、UI 小游戏运行时”的定位，目前主观评分 **8.5/10**。本轮完成批准方案中的五个改进阶段，重点提高验证可信度、类型约束和完整游戏生命周期的可靠性。现有证据尚不足以给出跨设备、跨浏览器、长时间商业运行的 10 分评价。

## 性能结果及边界

CPU 每项 3 次预热、30 次样本，10 项预算全部通过。示例分布：

| 负载 | P50 | P95 | 现有中位数预算 |
|---|---:|---:|---:|
| SpatialHash 插入 2 万并执行 2 万查询 | 24.82 ms | 32.32 ms | 400 ms |
| 2.5 万 swarm 更新 | 2.08 ms | 2.60 ms | 250 ms |
| 10 万 swarm 更新 | 8.24 ms | 11.58 ms | 80 ms |
| 1 万 VFX 粒子与 2000 popup | 0.45 ms | 0.75 ms | 2.5 ms |

GPU 视口为 960×540、DPR 1，预热 10 帧。前两项各采样 90 帧，压力场景采样 40 帧；每帧同步读取一个像素使排队渲染完成后才计时。

| 负载 | 硬件 P95 | 硬件最大值 | 软件 P95 | 软件最大值 |
|---|---:|---:|---:|---:|
| WebGL2D 1 万精灵 | 3.36 ms | 4.70 ms | 55.42 ms | 56.70 ms |
| 默认 Three 场景 | 2.85 ms | 3.70 ms | 16.40 ms | 16.80 ms |
| 2000 实例 + 64 灯 + post3d，中档 | 2.91 ms | 27.20 ms | 162.07 ms | 339.80 ms |

硬件 P95 预算为 16.67 ms；软件健康预算为普通渲染 250 ms、3D 压力 4000 ms。Canvas2D 为信息项，硬件/软件配置下的 1 万精灵 P95 分别为 12.11 / 12.45 ms。

压力场景两个路径均在第 49 个模拟步、1081 个可见实例、63 个活跃灯、33326 个三角形上结束。负载和姿态一致。硬件最大帧仍有 27.2 ms 尖峰；软件压力场景显著慢于实时帧预算。以上不能推导整款游戏、真实手机或所有图形组合均为 60 fps。

JSON 证据位于本地忽略目录 `build/performance/final-*.json`，视觉图像与对比报告位于 `build/visual-regression/`。这些包含本机环境字段的输出未加入公共仓库。

### 自适应画质复测

Chrome 157 与 SwiftShader 在 3840×2160、DPR 2、中档下启动时，画布为 1632×918。旧版收到足以降至 0.6 倍的慢帧后仍使用相同缓冲区。新版降至 979×551，像素数减少 64.0%，后处理尺寸与画布一致。移动视口模拟（844×390、DPR 2）同样验证了缓冲区对齐。在 960×540、DPR 1 下，慢帧触发中档降到低档后，画布维持 576×324。旧版在这一步回升到 768×432。

同一 4K 受控场景渲染 144 个实例并启用中档后处理。每个缩放值预热 5 帧、采样 15 帧，每帧同步读回一个像素。新版从 1.0 倍的 P50/P95 78.0/79.2 ms 降到 0.6 倍的 28.3/30.8 ms。旧版在 0.6 倍测得 74.8/77.6 ms。每次变更分配的后处理目标由最多 3 套降到 1 套。该探针使用注入的慢帧驱动画质切换，耗时来自软件渲染的合成场景。原始数据位于 `build/performance/adaptive-real-buffers.jsonl`。

本阶段 `npm run check:all` 通过 264 个主测试和 32 个 network 测试。7 种浏览器配置及固定基线视觉对比通过。软件渲染测试夹具和 WebAsset 硬件路径均通过两款参考游戏的完整生命周期、两次 WebGL 上下文恢复和 3D 缓冲区缩放检查。

### 五分钟耐久测试与页面缓存恢复

基于 `0d148e3` 的 WebAsset 游戏在 Chrome 157、RTX 4070、960×540、DPR 1 下各运行 300 秒。Survivor 以 3000 个敌人开局并点选 33 次升级。Arena 使用固定中档。测试使用参考游戏的无敌参数以持续施加负载。两款游戏四个时间窗均有战斗进展，P95/P99 为 7.0/7.1 ms，丢失模拟步和超过 50 ms 的帧均为零。

| 样板 | 实测时长 | 击杀 | 最长帧 | 四个检查点的回收后 JS 堆 |
|---|---:|---:|---:|---:|
| 2D Survivor | 300.06 s | 83,461 | 27.8 ms | 3757–4203 KiB |
| 3D Arena | 300.08 s | 105 | 20.9 ms | 6912–7081 KiB |

分位数来自每段最多 600 个动画帧间隔样本，最长帧来自全量计数。堆读数只覆盖 JS。原始报告位于 `build/performance/webasset-soak-300.jsonl`。

Chrome 还复现了从前进后退缓存返回时，两款旧样板的应用已被销毁。修复覆盖生成模板和样板游戏，`pagehide.persisted` 期间保留场景，真正退出时释放资源。原生导航探针移除了测试浏览器所见的本地 `no-store` 响应头，使页面满足缓存条件。两款修复后的样板各连续恢复两次，模拟步继续推进，按住的移动键已释放。原始报告位于 `build/performance/webasset-history-restore.jsonl`。

### 恢复前台计时与触控

Chrome 157 的前进后退缓存对照将页面挂起约 1.1 秒。使用 `481c8de` 的调度器时，Survivor 和 Arena 的恢复首帧分别收到 1111 和 1118 ms，两者都推进 5 个固定步并增加 10 个丢步。Survivor 的运行时诊断也记录了 1111 ms 的卡顿。

新版在可见性改变时重置动画时钟。两款游戏恢复首帧的时间增量为 0，固定步与丢步计数未增加，之后继续推进。Survivor 从首帧开始新的诊断窗口，隐藏时的帧不参与画质决策。原始记录位于 `build/performance/webasset-background-clock.jsonl`。

触控回归模拟按住拖杆时隐藏页面，验证平台指针与拖杆清零，返回后可以重新拖动。单元测试还验证缓冲中的屏幕按键动作被清除、普通短按仍可缓冲，以及画质回调中销毁应用后诊断窗口保持清空。

### 移动视口冷启动

同一台主机用 Chrome 157、SwiftShader、844×390、DPR 2 测试两款 WebAsset 样板，禁用浏览器 HTTP 缓存，CPU 节流 4 倍，模拟网络为 80 ms 延迟、5 Mbps 下载及 1 Mbps 上传。每款游戏改动前后各采一次冷启动，从导航开始计到引擎就绪标记。字节数为浏览器 Resource Timing 记录的子资源传输量。

| 样板 | 冷启动 | 子资源请求 | 传输量 |
|---|---:|---:|---:|
| 2D Survivor | 2.60 → 1.58 s | 79 → 46 | 0.98 → 0.54 MB |
| 3D Arena | 12.78 → 5.22 s | 92 → 55 | 7.12 → 2.74 MB |

模板及样板改用所需子模块，配置和核心依赖一起请求。Arena 的自有碰撞逻辑无需下载约 3.9 MB 的 Rapier 模块与 WASM。两款样板复测均正常渲染，软件路径的触控及两次 WebGL 上下文恢复通过。显式启用 Rapier 3D 的模板由浏览器请求回归覆盖。原始冷启动数据位于 `build/performance/mobile-software-profile.jsonl`。

标准打包后的 2D、Rapier 3D 和 UI 项目均在独立浏览器测试中启动成功。3D 项目请求了所选 WASM，2D、UI 与两款样板的浏览器启动未请求 Rapier。

在相同限速环境中对 Arena 交错测试三种预加载设置，每组 3 次冷启动。无提示、仅预加载 `three.core.js` 和同时预加载两个模块的中位数分别为 5.144、4.753 和 4.721 秒。两项预加载各只传输一次，该组每轮请求 55 个子资源，共约 2.74 MB。3D 模板和 Arena 采用两项提示，WebAsset 正式入口在一次独立冷启动中于 4.814 秒就绪。原始记录位于 `build/performance/arena-modulepreload.jsonl`。

标准 Rapier 3D 包与 Bilibili Toy 3D 包均在本地 Chromium 通过启动及单次模块请求检查。Toy ZIP 通过预检，带内容指纹的入口从子目录启动成功。

## 验收与工程判断

批准设计中的 10 项条件均有对应证据：1 视觉/失败保护、2 严格消费者、3 稳定性来源、4 分布/卡顿、5 完整游戏流程、6 缺陷回归/变更日志、7 分阶段 check 与最终 check:all、8 对应浏览器/CPU/UI检查、9 main 上聚焦提交并逐次推送、10 本报告的环境和覆盖边界。已推送的阶段提交包括 `9f7c6b6`、`e67ec13`、`e9d802f`、`31ed2f8`；最终修复及本报告随收尾提交交付。

后续复验中，两款参考游戏在 Firefox 150.0.2 和 Windows Playwright WebKit 18.2 均完成三轮战斗死亡与重开、刷新存档和销毁。Chrome 157 的 844×390、DPR 2 触摸模拟还验证了拖动、取消后指针清零、角色停止移动及点按重开，同一套流程也在 WebAsset 上通过。Chromium 触摸模式已加入 CI。Windows Playwright WebKit 提供另一种浏览器引擎的证据，物理 iOS 和 Safari 仍待测试。

在 Chrome 157 的同一画布上，WebGL2D 与 Three 各创建、渲染并销毁 50 个应用。每轮验证了应用停止、场景注册表清空、实体解除绑定及重复销毁行为，未出现浏览器警告或错误。手动回收垃圾后，第 5 到第 50 轮的 JS 堆读数分别从 2249 增至 2427 KiB、从 5900 增至 6451 KiB。这是短时观测，GPU 内存和长时间运行仍待测。另一个聚焦测试复现并修复了销毁监听器抛错后输入仍可接收按键的问题，此后 `npm run check` 通过 243 项。

新增的 WebGL 恢复检查通过 `WEBGL_lose_context` 让两款游戏各丢失并恢复两次实际上下文。SwiftShader 测试夹具和 WebAsset RTX 4070 路径都恢复了场景像素，逻辑帧继续推进，GL 错误为零。桌面 Chromium CI 现在运行这项检查。节点测试还复现并修复了暂停、恢复在同一回调内重入时排入两个动画帧，以及就绪回调抛错后应用无法重试启动的问题。`check:all` 通过 246 个主测试、32 个 network 测试及构建。

两款 WebAsset 游戏也分别在 Chrome 157、RTX 4070、960×540 上完成了 120 秒主动输入探测（引擎 `35e4bc5`）。Survivor 以 3000 个敌人开局，脚本点选 23 次升级，最终推进到第 7206 个模拟步并击杀 8761 个敌人。四个时间窗的 P95 为 7.0 ms、P99 为 7.1 ms，回收后的堆为 3627–4497 KiB。中档 Arena 在 120.3 秒内推进 7215 个模拟步，P95 为 7.0 ms、P99 为 7.1 ms，末四次回收后的堆为 7067–7129 KiB。两次探测都没有浏览器错误。调度修复后用正式长跑命令各复跑 30 秒，四段模拟与战斗进度检查均通过，无掉步和超过 50 ms 的帧，P95/P99 仍为 7.0/7.1 ms。这里的分位数来自普通动画帧间隔，独立渲染负载仍以同步读回基准为准。

带贴图的 WebGL2D 恢复回归曾复现图像消失和 GL 1282。重置纹理缓存后，同一图像对象和两个同尺寸自绘精灵在连续两次恢复后的采样像素分别为 256、256、128，GL 错误为零。另一项 RTX 4070 对照使用 400 帧动态文本及 800 次自绘回调。旧版在第 100、200、300、400 帧额外留存 300、600、900、1200 个 WebGL 纹理对象，修复后为 101、129、129、129。销毁后计数归零。计数通过浏览器的纹理创建与删除调用采集，范围仅限探针开始后创建的纹理对象。独立审阅补出了自绘状态串扰和上传异常后的重试问题，两者都有回归覆盖。

修复后 `check:all` 通过 249 个主测试和 32 个 network 测试。两款参考的视觉对比继续通过。1 万精灵的 WebGL2D 同步读回基准在 RTX 4070 和 SwiftShader 上分别得到 1.70 ms 和 51.76 ms 的 P95，均通过各自预算。自绘退回普通 HTML Canvas 并通过宽度赋值复位的路径也用真实像素核验过。

Model3D 的所有权回归覆盖前后版本的实例共享资产、未完成的加载、共享骨骼纹理以及 `awake()` 前销毁。使用 RTX 4070 在已注册的 Arena 中重复 50 轮同键模型替换、渲染和销毁。旧版 `ba273b7` 的 Three 几何计数从 15 增到 65，100 个几何只有 50 个触发释放。修复后每个十轮检查点都维持 15，100 个几何全部释放。同一探针还渲染了骨骼实例，纹理计数从 3 增至 4，实例销毁后回到 3。模型提供器销毁后共享源几何回到探针基线。测试通过同一 Three 渲染器的几何和纹理计数，以及资源的 `dispose` 事件验证。

## 执行中的全部取舍

1. Bash 入口不可用时以原生文件工具记录同样的进度账本。误判代价是少了技能启动脚本的格式校验。
2. 按仓库要求在 main 原工作区实施，覆盖技能通用 worktree 建议。误判代价是无法依赖分支隔离；以精确暂存保护用户改动。
3. 串行运行浏览器/渲染套件以避免 GPU 和截图争用。误判代价是核验耗时增加。
4. 声明生成启用 strictNullChecks，修正不准确的历史空值约束。误判代价是下游 TypeScript 会暴露原先未报出的空值错误。
5. 严格消费者移除 skipLibCheck，检查完整声明图并修复缺失导入和选项。误判代价是更严格的消费者检查和声明生成维护成本。
6. 压力测试固定中档并同步读回，保持 GPU 路径间可比较。误判代价是该分布不代表自动画质或未同步的实际呈现延迟。
7. 新 WebAsset 示例使用自带当前运行时的副本，避免改动服务或依赖旧共享运行时。误判代价是副本可能过时，需要重新部署。
8. 完整流程测试使用已有模拟 API 加速和 1500 敌人压力，避免随机升级造成不定长死亡等待。误判代价是不能代替长时间平衡/设备测试。
