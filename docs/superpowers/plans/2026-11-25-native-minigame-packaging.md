# 微信与抖音小游戏打包实施计划

**交付目标**　在 HGame 的同一个打包入口生成微信和抖音原生小游戏工程及 ZIP。

## 构建与启动

- [x] 用 `tests/minigame-package.test.mjs` 固定双端命令与平台配置，验证 ZIP 顶层结构、资源白名单、包体限制及构建失败保留上一次发布包。先确认原打包器拒绝这两个目标。
- [x] 在 `scripts/package-game.mjs` 加两个目标，沿用现有版本命名、发布暂存和确定性 ZIP。以独立 `minigame.config.json` 声明入口、屏幕方向和资源，esbuild 将同一入口编译成平台原生 `game.js`。
- [x] 让同一 Canvas 样板在只有 `wx` 或 `tt` 的测试环境里运行。检查渲染、触控、包内读取、存档、音频、窗口大小和前后台事件。宿主能力通过 `start(host)` 注入。
- [x] 将打包模块纳入生成项目和显式同步，并说明现有 HTML 游戏如何提供原生入口。保留标准与 Toy 回归测试。

## 验收

重新构建双端样板，执行新增测试与 `npm run check`，审查变更后按仓库规则提交并推送 `main`。平台开发者工具与真机结果单独记录。
