# HGame 3D 模型顶点、面数与多级 LOD 统一资产规范（支持十万人同屏架构）

> **适用范围**：`hgame` 引擎全量 3D 静态与角色资产、Blender 离线清洗管线（[`webasset/hgame-assets-cn/blender/clean_and_lod.py`](../../webasset/hgame-assets-cn/blender/clean_and_lod.py)、[`scripts/blender-model3d.py`](../../scripts/blender-model3d.py)、[`scripts/process-model3d.mjs`](../../scripts/process-model3d.mjs)）、[`assets/runtime/integrations/model3d/bone-vat.js`](../../assets/runtime/integrations/model3d/bone-vat.js) 群集渲染、[`assets/runtime/world/swarm-ecs.js`](../../assets/runtime/world/swarm-ecs.js) 调度层以及 Web / 小游戏多端运行环境（哔哩哔哩 toy、微信、抖音、TapTap、PC WebGL2）。  
> **核心原则**：**资产侧唯一标准，运行时动态定档**。所有角色均按同一套 T5 规范统一生产，不区分主角、NPC 与群集兵种；同一角色 `.glb` 既可直接作为近景主角，也可通过运行时追加 `LOD4` 与 16 字节压缩实例架构，无缝撑起同屏十万人规模。

## 一、核心概念：资产档位（Tier）与细节层级（LOD）

本规范由**横纵两个维度**共同约束：

- **T0–T5（资产预算档位 / Tier）**：横向按物体类别划分的**入库面数天花板**与**远景降级策略**（决定清洗脚本按哪条红线减面）。
- **LOD0 / LOD1 / LOD2 / LOD3 / LOD4（细节层级 / Level of Detail）**：纵向针对**同一个模型**随屏幕投影占比缩小或同屏数量暴涨时，自动切换的简化网格、着色降级与点精灵/微群贴片版本。

## 二、T0–T5 统一预算与多级 LOD 总表

| 档位 | 资产类别 | 典型代表 | LOD0（近景精模上限） | LOD1（中景减面） | LOD2 及超远景策略 |
|---|---|---|---|---|---|
| **T0** | 建筑模数 | 墙体、柱子、楼板、屋顶模块 | **≤ 1,000 三角面** | 保 UV 自动减面（40%–50%） | 极简几何体或远景 Impostor |
| **T1** | 小型杂物 | 杯子、瓶子、砖块、桌面摆件 | **≤ 300 三角面** | 自动减面（40%–50%） | 远景 Impostor 或按屏幕占比直接剔除（Cull） |
| **T2** | 道具与家具 | 桌椅、货架、木箱、路灯、柜子 | **≤ 1,500 三角面** | 保 UV 自动减面（35%–50%） | 远景 Impostor / 极简轮廓盒 |
| **T3** | 自然生态与植被 | 树木、灌木、大型植物、岩石群 | **≤ 3,000 三角面** | 枝叶稀疏化保 UV 减面 | **4–8 面十字面片 Impostor** |
| **T4** | 载具与大型交互物 | 轿车、卡车、机械设备、大型设施 | **≤ 4,500 三角面** | 保轮廓减面（35%–45%） | **≤ 500 面 / ≤ 610 GPU 顶点**；将车轮等独立子部件**焊死合并进车身**以压低 Draw Call |
| **T5** | **全角色统一标准**（所有角色通用） | 全部人形/类人形角色（不区分主角与杂兵） | **推荐 ≤ 6,000 面 / ≤ 7,500 顶点**<br>*(复杂配饰硬上限 ≤ 8,000 面 / ≤ 10,000 顶点)* | **~1,500–1,800 三角面**（2 权重） | **LOD2**：**~300–450 面**（1 权重刚性蒙皮）<br>**LOD3**：**6–8 面紧包多边形 Impostor**（0 骨骼，8 方位）<br>**LOD4（运行时生成）**：**1 顶点 `GL_POINTS` 点精灵**或 2 面广告牌（复用 LOD3 图集低阶 Mip） |

> **说明**：所有档位的 `LOD0 / LOD1 / LOD2` 均采用**单文件内嵌多级 LOD** 打包，并强制共享同一套贴图与材质（Impostor 专用图集除外）。`LOD4` 完全由运行时接管生成，**无需美术或 Blender 多导出任何网格**。

## 三、T5 统一角色 5 级 LOD 退化阶梯（兼顾近景特写与十万人同屏）

所有角色在 `blender-model3d.py` 导出时**一律只生成固定资产层级（`LOD0–LOD2` 蒙皮网格 + 可选紧包 `LOD3` Impostor）**，原生对齐 `bone-vat.js` 的 HalfFloat Bone-VAT + 5-LOD（`lodMode: 't5-5lod'`）架构；超远距 `< 0.012` 由引擎运行时无缝切入 `LOD4`。

### 3.1 各档位几何、骨骼权重与着色降级标准

| 档位 | 生产归属 | 三角面 / 几何规格 | 每顶点最大骨骼权重 | 着色与阴影策略 | 屏幕高度占比 (`1080p` 像素高) |
|---|---|---|---|---|---|
| **LOD0** | 资产离线导出 | **≤ 6,000 面**<br>*(硬上限 8,000)* | **4 权重**（23 骨实时蒙皮 / VAT 插值） | 完整 PBR（`Color` + `Normal_RM`）+ 实时阴影投射 | `>= 0.16` (≥ 173 px) |
| **LOD1** | 资产离线导出 | **1,500–1,800 面** | **降至 2 权重**（23 骨 VAT） | 完整 PBR（`Color` + `Normal_RM`）+ 实时阴影投射 | `0.07 – 0.16` (76–173 px) |
| **LOD2** | 资产离线导出 | **300–450 面** | **降至 1 权重（刚性蒙皮）**，关闭帧间插值（最近整数帧采样） | **关闭 `Normal_RM`**，仅 `Color` + 简版方向光 + 脚底圆片假影（关闭 ShadowMap） | `0.025 – 0.07` (27–76 px) |
| **LOD3** | 资产离线导出 | **6–8 面紧包多边形**<br>*(严禁使用 2 面矩形)* | **0 骨骼**（8 方位 Y 轴锁定动画 Impostor） | 纯序列帧 KTX2 图集采样（无光照计算，接触阴影烘焙在底边） | `0.012 – 0.025` (13–27 px) |
| **LOD4** | **引擎运行时接管** | **1 个 `GL_POINTS` 点精灵**<br>*(驱动不兼容时回退 2 面广告牌)* | **0 骨骼**（复用 LOD3 图集低阶 Mipmap） | 极简点采样，**关闭 `discard` 复杂裁剪**，无光照与阴影，防亚像素噪点闪烁 | `< 0.012` (< 13 px) |

### 3.2 关键底层减负机制
1. **LOD2 刚性 1 权重蒙皮**：屏幕高度低于 7% 时肉眼无法分辨关节平滑融合。导出 `LOD2` 时执行 `limit_total(1)` 并归一化，配合关闭帧间插值，Vertex Shader 的 VAT 纹理采样次数从 **24 次骤降至 3 次**，显存带宽节省 **87.5%**。
2. **LOD3 紧包切边多边形（Tight Mesh）**：离线烘焙 Impostor 时沿角色剪影切出 6–8 面紧凑多边形（`buildTightImpostorGeometry`），相比 2 面矩形削减移动端 TBDR GPU **40%–60%** 的透明像素过绘（Alpha-Test Overdraw）。动作仅烘焙高频通用 4 条（待机、跑、攻击、死亡），采样帧率压至 **10–12 fps**。
3. **LOD4 消除 2×2 Quad Helper Lane 浪费**：投影高度低于 13 像素时，6–8 面紧包多边形会导致超过 60% 的片元着色器算力浪费在极小三角面的边沿辅助像素上。切入 `GL_POINTS` 点精灵（或 2 面极简广告牌）并采样低阶 Mip，可将超远景渲染开销降至理论极限。

### 3.3 十万人同屏渲染桶硬上限与面数核算（PC / 移动端）
分桶实例化（Bucketed Instancing，`T5_CROWD_BUCKET_LIMITS`）必须执行**渲染桶配额硬上限截断**（高档位桶满后，新落入的单位直接溢流至下一级 LOD 桶），彻底锁死全屏几何与带宽天花板：

| 档位 | PC 桶硬上限 | 移动端桶硬上限 | 10 万人满载面数 (PC) | 10 万人满载面数 (移动端) |
|---|---:|---:|---:|---:|
| **LOD0** | **≤ 15 人** | **≤ 6 人** | ~9.0 万 | ~3.6 万 |
| **LOD1** | **≤ 80 人** | **≤ 35 人** | ~12.8 万 | ~5.6 万 |
| **LOD2** | **≤ 1,200 人** | **≤ 500 人** | ~42.0 万 | ~17.5 万 |
| **LOD3** | **≤ 12,000 人** | **≤ 4,000 人** | ~7.2 万 | ~2.4 万 |
| **LOD4** | **其余 86,705 人** | **其余 95,459 人** | **~17.3 万面** *(点精灵仅 8.7 万顶点)* | **~19.1 万面** *(点精灵仅 9.5 万顶点)* |
| **合计** | **100,000 人** | **100,000 人** | **~88.3 万面** | **~48.2 万面** |

### 3.4 运行时实例级控制开关（取代资产拆分）
同一角色 `.glb` 在不同玩法中的表现完全由运行时参数控制（`spawn({ priority, minLod })` / `setInstanceLodPolicy`）：
- **`priority`（保级权）**：玩家自身或镜头聚焦单位设为高优先级（`priority > 0`），优先占用 `LOD0` 桶配额，不被周围单位挤出。
- **`minLod`（最低起步档位）**：普通动作/射击玩法默认为 `0`；万人割草/史诗攻城玩法可将普通单位设为 `minLod: 1` 或 `2`，直接跳过近景高模。

## 四、十万人同屏运行时底层架构规范（WebGL2 + WASM）

当同屏突破万级向十万级迈进时，瓶颈从“三角面数”转移为 **每帧显存上传带宽、CPU 遍历排序、寻路避障与亚像素过绘**，引擎群集模块（`bone-vat.js` + `swarm-ecs.js`）满足以下 4 项硬性实现规范：

### 4.1 16 字节压缩实例缓冲（严禁每单位传 64 字节 `mat4`）
100,000 人传 `mat4` 每帧需上传 6.4 MB（60 FPS 下高达 384 MB/s）。十万级群集实例化强制使用 **16 字节 / 实例（1.6 MB / 帧，带宽直降 75%）**，对应 `CrowdInstance16B`（`packCrowdInstanceBitfield` / `unpackCrowdInstanceBitfield` + `instanceFormat: 'bitpacked16'`）：

```text
Struct CrowdInstance16B (16 Bytes / 1x vec4 or uvec4):
├── [Bytes  0..11] pos: Float32 x 3   // 世界坐标 (x, y, z)
└── [Bytes 12..15] packed: Uint32     // 32 位位打包元数据：
      ├── bits  0..9  (10 bit): yaw 朝向角 (0..1023 映射 0°..360°，精度 ~0.35°)
      ├── bits 10..13 ( 4 bit): animId 动作索引 (支持 16 种动作态)
      ├── bits 14..23 (10 bit): animSeed 动画随机相位偏移
      └── bits 24..31 ( 8 bit): flags / 阵营色索引 / 受击闪烁 / 缩放微调
```

- 旋转矩阵与当前帧时间 `phase = fract(uTime * speed + animSeed)` **全部在 Vertex Shader 内实时计算**，CPU 无需逐帧更新动画计时器。

### 4.2 WASM + SoA 线性内存与 O(N) 空间块零排序分桶
1. **禁用 JS 对象数组**：严禁为十万单位分配 JS Object 或调用 `Array.sort()`（避免主线程超时与 GC 停顿）。
2. **SoA（Structure of Arrays）+ WASM**：所有单位的坐标、速度、朝向、状态、生命值存储在连续的 `Float32Array` / `Uint32Array` 线性内存中（`swarm-ecs.js` SoA），由 WASM 或批量调度完成逻辑推演，主线程仅将打包好的连续 16B TypedArray 通过增量更新范围上传 GPU。
3. **Chunk 粗剔除 + O(N) 零排序分桶**：地图划分为固定尺寸的 2D 空间块（Chunk），先执行块级视锥剔除；仅遍历可见 Chunk 内的单位，按屏幕高度占比直接落入 `LOD0–LOD4` 五个预分配桶（高优 `priority` 单位先入桶，普通单位遇桶满即顺延溢流，全程 $O(N)$ 无排序）。

### 4.3 群体寻路与避障（严格线性 $O(N)$）
严禁在万级以上规模使用单单位 A* 寻路或 $O(N^2)$ 个体碰撞检测：
- **流场寻路（Flow Field）**：基于 `128×128` 或 `256×256` 2D 网格（`FlowField2D`）生成目标方向向量场，十万单位每帧 $O(1)$ 查表获取行进向量。
- **网格密度推挤（Grid Density / PBD）**：每帧将单位分布累加至 2D 密度网格（`cellDensity`），通过密度梯度将高密度格内的单位向低密度格推开，实现自然的大军推挤洪流效果。

### 4.4 过绘压制（Early-Z）与移动端动态密度折叠
1. **强制从近到远绘制（Front-to-Back）**：渲染管线严格按 `LOD0 -> LOD1 -> LOD2 -> LOD3 -> LOD4` 设置 `renderOrder`（`0..4`）提交 Draw Call，利用 GPU **Early-Z** 剔除被前排角色遮挡的远景重叠片元，抑制十万人叠加的填充率爆炸。
2. **移动端广角俯瞰动态密度折叠（Macro Batching）**：
   - PC 端 WebGL2 可直接以完整 10 万实例稳定运行。
   - 移动端小游戏（微信 / B 站手机端）在全图广角俯瞰、大量单位落入 `LOD4` 时，启用**微群贴片折叠（`mobileMacroBatch`）**：将同一空间网格内每 `4–9` 个 `LOD4` 单位合并为 1 个“小方阵微群贴片”实例渲染，在保持十万大军视觉密度的前提下，将移动端 GPU 实际绘制实例数压至 **1.5 万–2 万级**，防止手机发热降频。

## 五、全局几何、顶点、贴图与骨架硬性红线

所有入库模型（T0–T5 通用）必须无条件通过以下约束：

### 5.1 顶点与索引缓冲限制
1. **单网格 GPU 顶点上限 ≤ 65,535**：强制使用 **16 位顶点索引（`Uint16Array`）**，严禁退化为 32 位索引（`Uint32Array`）。
2. **剔除冗余顶点属性**：
   - 严禁导出 `TANGENT`（切线）属性。
   - 清理未使用的多套 `UV`（仅保留 `TEXCOORD_0`）与无效顶点色（`COLOR_0`）。
3. **几何清洗必选操作**：导出前执行 `weld`（顶点焊接）、`dedup`（数据去重）、移除退化三角面与孤立顶点、统一逆时针（CCW）面朝向。

### 5.2 贴图、材质与纹素规范
1. **纹素密度（Texel Density）**：统一锁定为 **`512 px/m`**。
2. **双贴图极简 PBR 架构**：采用 **KTX2 硬件压缩** + **2 贴图结构**：
   - 贴图 1：`Color`（BaseColor / Albedo）
   - 贴图 2：`Normal_RM`（法线与粗糙度/金属度通道打包）
3. **跨 LOD 共享材质**：同一资产的 `LOD0 / LOD1 / LOD2` 必须引用同一套 KTX2 贴图与材质资源。

### 5.3 空间尺度与 T5 统一骨架规范
1. **米制与原点**：严格遵循 `1 unit = 1 meter`（标准人形高 `1.70m–1.80m`）；原点对齐**底面中心 `(0, 0, 0)`**，确保碰撞体、地面接触与挂点坐标一致。
2. **T5 统一 23(+3) 骨架**：
   - 严格使用 23 根基础人形骨（UE5 Mannequin 命名），**强制保留位于 `(0, 0, 0)` 的 `root` 关节作为 `pelvis` 父节点**，杜绝 22 骨（缺 `root`）与 23 骨混用。
   - 检测到尾巴/披风时自动追加 3 根附属骨（`tail_01..03` 或 `cape_01..03`），运行时由程序化弹簧骨驱动。
   - 0 手指骨、0 Twist 骨、0 UE IK 虚拟骨；武器通过 JSON Socket 挂点（主手 `hand_r`、盾牌 `lowerarm_l`、背挂 `spine_03`）+ 双骨解析 IK 对齐。

## 七、运行时 LOD 切换与 1.12 倍迟滞防抖规则

1. **屏幕高度占比驱动（Screen Height Ratio）**：
   ```text
   screenHeightRatio = projectedBoundingSphereHeightPx / viewportHeightPx
   ```
   T5 统一角色切换阈值：`LOD0 (>= 0.16)` -> `LOD1 (0.07–0.16)` -> `LOD2 (0.025–0.07)` -> `LOD3 (0.012–0.025)` -> `LOD4 (< 0.012)`。
2. **1.12 倍迟滞防抖（Hysteresis）**：
   - 降级（如 `LOD0 -> LOD1`）：`screenHeightRatio < threshold` 时触发。
   - 升级（如 `LOD1 -> LOD0`）：必须回升至 `screenHeightRatio > threshold * 1.12` 时才切回高模，防止相机微动引起模型闪烁。

## 八、资产入库与运行时自动质检门禁（验收清单）

### 8.1 离线资产入库门禁（任意红线失败直接阻断入库）
- [ ] **档位与面数合规**：已标注 `tier`（`T0`–`T5`），各 LOD 三角面数与顶点数未超上限（T5 统一：`LOD0` ≤ 6,000 推荐 / ≤ 8,000 硬上限，`LOD1` 1,500–1,800，`LOD2` 300–450，`LOD3` 6–8 面紧包片）。
- [ ] **16 位索引合规**：任意子网格 GPU 顶点数 `<= 65,535`，索引格式为 `UNSIGNED_SHORT`（`Uint16Array`）。
- [ ] **权重降级合规（T5）**：`LOD0` ≤ 4 权重、`LOD1` ≤ 2 权重、`LOD2` 严格为 1 权重且已归一化。
- [ ] **属性与几何干净**：无 `TANGENT` 属性、无冗余 UV/顶点色、已完成 `weld` 与 `dedup`。
- [ ] **贴图与 Mipmap 合规**：纹理为 KTX2 格式，符合 `Color + Normal_RM` 双贴图结构，纹素密度 `512 px/m`，`LOD0–LOD2` 共享同一套贴图材质；`LOD3` Impostor 图集已生成完整 Mipmap 链以支撑 `LOD4`。
- [ ] **空间与骨架合规**：米制尺度正确、底面中心为 `(0, 0, 0)`；T5 统一为 23(+3) 骨标准且强制包含 `root` 节点。

### 8.2 十万人群集运行时门禁（压测验收）
- [ ] **实例压缩合规**：群集实例缓冲严格为 `16 Bytes / instance`，无 `mat4` 传输，动画相位在 Shader 内计算。
- [ ] **零排序与内存合规**：十万单位全量托管于 WASM / TypedArray SoA 线性内存，主线程无每帧对象分配与 `Array.sort()`。
- [ ] **桶上限与绘制顺序合规**：各 LOD 桶硬上限生效、溢流降级无越界；Draw Call 严格按 `LOD0 -> LOD4` 从近到远提交。
- [ ] **移动端折叠策略合规**：移动端检测到 `LOD4` 占比过高时正确触发 Macro Batching（微群贴片折叠），实际 GPU 绘制实例数受控。
