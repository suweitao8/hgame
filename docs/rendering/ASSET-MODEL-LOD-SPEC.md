# HGame 3D 模型顶点、面数与多级 LOD 资产规范

> **适用范围**：`hgame` 引擎全量 3D 静态与动态资产、Blender 离线清洗管线（`webasset/hgame-assets-cn/blender/clean_and_lod.py`、`scripts/blender-model3d.py`）、`assets/runtime/integrations/model3d/bone-vat.js` 群集渲染以及 Web / 小游戏多端运行环境（哔哩哔哩 toy、微信、抖音、TapTap、PC WebGL2）。  
> **核心目标**：在 512 px/m 写实纹素标准下，通过 **T0–T5 预算分级 + 单网格 16 位索引硬红线 + 屏幕高度占比多级 LOD**，兼顾近景画质与移动端/网页端高帧率表现。

---

## 一、核心概念：资产档位（Tier）与细节层级（LOD）

本规范由**横纵两个维度**共同约束，严禁混为一谈：

- **T0–T5（资产预算档位 / Tier）**：横向按物体类别与视觉重要度划分的**入库面数天花板**与**远景降级策略**（决定 `clean_and_lod.py` / `blender-model3d.py` 按哪条红线减面、远景是转十字面片还是焊死子部件）。
- **LOD0 / LOD1 / LOD2（细节层级 / Level of Detail）**：纵向针对**同一个模型**随屏幕投影占比缩小而切换的几何简化版本（决定引擎运行时当前帧该渲染哪一档网格）。

---

## 二、T0–T5 分级面数、顶点与多级 LOD 预算表

| 档位 | 资产类别 | 典型代表 | LOD0（近景精模上限） | LOD1（中景减面目标） | LOD2 / 超远景降级策略 |
|---|---|---|---|---|---|
| **T0** | 建筑模数 | 墙体、柱子、楼板、屋顶模块 | **≤ 1,000 三角面** | 保 UV 自动减面（约 40%–50%） | 极简几何体或远景 Impostor |
| **T1** | 小型杂物 | 杯子、瓶子、砖块、桌面小摆件 | **≤ 300 三角面** | 自动减面（约 40%–50%） | 远景 Impostor 或按屏幕占比直接剔除（Cull） |
| **T2** | 道具与家具 | 桌椅、货架、木箱、路灯、柜子 | **≤ 1,500 三角面** | 保 UV 自动减面（约 35%–50%） | 远景 Impostor / 极简轮廓盒 |
| **T3** | 自然生态与植被 | 树木、灌木、大型植物、岩石群 | **≤ 3,000 三角面** | 枝叶稀疏化保 UV 减面 | **4–8 面十字面片 Impostor** |
| **T4** | 载具与大型交互物 | 轿车、卡车、机械设备、大型设施 | **≤ 4,500 三角面** | 保轮廓减面（约 35%–45%） | **≤ 500 面 / ≤ 610 GPU 顶点**；将车轮等独立子部件**焊死合并进车身**以压低 Draw Call |
| **T5** | 骨骼角色（英雄 / NPC） | 玩家主角、重要 BOSS、普通 NPC、群集敌人 | • **英雄角色（`--preset hero`）**：**≤ 9,000 面 / ≤ 11,000 顶点**<br>• **普通 NPC（`--preset low`）**：**≤ 6,000 面 / ≤ 7,500 顶点** | 目标降至 **~2,200 三角面**（约 35% 比例，LOD1 切换阈值 `0.12`） | 结合 `bone-vat.js`（HalfFloat Bone-VAT + 3-LOD），远景采用极简静态网格或 **8 方位 Y 轴锁定 Impostor** |

> **说明**：所有等级的 `LOD0 / LOD1 / LOD2` 均采用**单文件内嵌多级 LOD** 规范打包，并强制共享同一套贴图与材质，避免多级 LOD 造成显存翻倍。

## 三、全局几何、顶点与贴图硬性红线

所有入库模型（无论 T0–T5 哪个档位）必须无条件通过以下硬性约束：

### 3.1 顶点与索引缓冲限制
1. **单网格 GPU 顶点上限 ≤ 65,535**：强制使用 **16 位顶点索引（`Uint16Array`）**，严禁退化为 32 位索引（`Uint32Array`），以节省显存和传输带宽。
2. **禁止冗余顶点属性**：
   - 严禁导出 `TANGENT`（切线）属性（由片元着色器按屏幕导数或既定法线方案计算）。
   - 清理未使用的多套 `UV`（无光照贴图需求时仅保留 `TEXCOORD_0`）与无效顶点色（`COLOR_0`）。
3. **几何清洗必选操作**：导出前执行 `weld`（顶点焊接）、`dedup`（数据去重）、移除退化三角面与孤立顶点、统一逆时针（CCW）面朝向。

### 3.2 贴图、材质与纹素规范
1. **纹素密度（Texel Density）**：统一锁定为 **`512 px/m`**，确保同场景内建筑、道具、载具与角色表面清晰度一致。
2. **双贴图极简 PBR 架构**：采用 **KTX2 硬件压缩** + **2 贴图布局**：
   - 贴图 1：`Color`（BaseColor / Albedo）
   - 贴图 2：`Normal_RM`（法线与粗糙度/金属度通道打包）
3. **跨 LOD 材质共享**：同一资产的 `LOD0 / LOD1 / LOD2` 必须引用完全相同的 Material 与 KTX2 纹理引用，禁止为低级 LOD 单独生成独立材质球（Impostor 专用图集除外）。

### 3.3 空间尺度、原点与骨架对齐
1. **米制单位**：严格遵循 `1 unit = 1 meter`（标准人形高度约 `1.70m–1.80m`）。
2. **原点与碰撞一致性**：模型原点统一对齐**底面中心 `(0, 0, 0)`**，静态与动态资产的物理碰撞体、交互挂点（Socket）必须与底面原点坐标对齐。
3. **T5 角色骨架绑定规范**：
   - 统一采用 **23 根基础人形骨**（强制保留位于 `(0, 0, 0)` 的 `root` 节点作为 `pelvis` 父节点），检测到尾巴/披风时追加 **+3 根附属骨**（共 26 根）。
   - 0 手指骨、0 Twist 骨、0 UE IK 虚拟骨；武器通过 JSON Socket 挂点 + 运行时双骨 IK 对齐。

## 四、离线自动化生产管线

禁止美术或 AI 手工随意减面破坏 UV 与原点，全部资产通过离线脚本批处理入库：

| 资产类型 | 责任脚本 / 工具 | 自动化处理流程 |
|---|---|---|
| **T0–T4 静态 / 扫描高模** | `webasset/hgame-assets-cn/blender/clean_and_lod.py` | 1. 校准米制比例与底面原点<br>2. 执行 `weld` / `dedup` / 清理 `Tangent` 与废属性<br>3. 对高面数扫描件执行**保 UV 减面**或**高模烘低模**（对齐 512 px/m + KTX2 2 贴图）<br>4. 按 T0–T4 档位自动生成 `LOD1` / `LOD2`（T3 转十字片、T4 焊死车轮与子部件）并单文件内嵌打包 |
| **T5 骨骼角色模型** | `scripts/blender-model3d.py` + `npm run anim:bake` | 1. 规范化 23(+3) 骨架并强制输出 `root`<br>2. 控制 LOD0 面数在 6,000–9,000 面区间（NPC ≤ 6,000 面 / ≤ 7,500 顶，Hero ≤ 9,000 面 / ≤ 11,000 顶），生成 ~2,200 面的保权重 `LOD1` 与远景简化级<br>3. 群集角色配合 `bone-vat.js` 烘焙 HalfFloat `.vat.bin` 3-LOD 资产 |

### 单文件内嵌 LOD 节点命名约定
为便于引擎加载器自动识别与分桶，单 `.glb` 内的层级节点统一采用后缀约定：
- `*_LOD0`：近景主网格
- `*_LOD1`：中景减面网格
- `*_LOD2`：远景极简网格或 Impostor 节点
- `*_COL`（可选）：简化物理碰撞体（不参与渲染）

## 五、运行时 LOD 切换与合批机制

### 5.1 屏幕高度占比驱动（Screen Height Ratio）
引擎不采用固定世界距离切 LOD，而是实时计算模型包围球投影到屏幕上的**垂直高度占比（`screenHeightRatio`）**：

```text
screenHeightRatio = projectedBoundingSphereHeightPx / viewportHeightPx
```

- **参考切换阈值（按档位可微调，T5 已锁定）**：
  - **T5 骨骼角色**：`LOD0 -> LOD1` 切换阈值 = **`0.12`**；更低占比切入 `LOD2` / 8 方位 Y 轴锁定 Impostor。
  - **T0–T4 静态与载具**：依据档位表设定 `LOD0 -> LOD1 -> LOD2 -> Cull` 阈值，确保模型在屏幕像素足够小时平滑降级或剔除。

### 5.2 1.12 倍迟滞防抖（Hysteresis）
为防止相机微动或角色在临界点徘徊导致 LOD 反复跳级闪烁，所有降级与升级阈值引入 **1.12 倍迟滞区间**：
- **降级（如 LOD0 -> LOD1）**：当 `screenHeightRatio < threshold` 时触发。
- **升级（如 LOD1 -> LOD0）**：必须回升至 `screenHeightRatio > threshold * 1.12` 时才切回高模。

### 5.3 分桶实例化（Bucketed Instancing）
- 运行时根据每个实例当前的 `screenHeightRatio`，将其动态分配至对应的 `LOD0`、`LOD1`、`LOD2` 渲染桶中。
- 同桶内实例通过 `InstancedMesh` / `bone-vat.js` 一次性合批绘制，将大规模场景与同屏群集单位的 Draw Call 压至最低。

## 六、资产入库自动质检门禁（验收清单）

所有通过脚本生成或第三方导入的模型，入库前必须全部满足以下校验项（任意红线失败直接阻断入库）：

- [ ] **档位合规**：已明确标注 `tier`（`T0`–`T5`），且 `LOD0` / `LOD1` / `LOD2` 三角面数与 GPU 顶点数未超该档位上限。
- [ ] **16 位索引合规**：任意子网格 GPU 顶点数 `<= 65,535`，索引类型为 `UNSIGNED_SHORT`（`Uint16Array`）。
- [ ] **属性干净**：无 `TANGENT` 属性，无冗余 UV/顶点色，已完成 `weld` 与 `dedup`。
- [ ] **贴图与共享合规**：纹理为 KTX2 格式，符合 `Color + Normal_RM` 双贴图结构，纹素密度对齐 `512 px/m`，各级 LOD 共享同一套贴图材质。
- [ ] **LOD 结构合规**：单文件正确内嵌 `LOD0 / LOD1 / LOD2`（T3 LOD2 为 4–8 面十字片；T4 LOD2 ≤ 500 面 / ≤ 610 顶点且子部件已焊死；T5 LOD1 ~2,200 面且权重过渡无破面）。
- [ ] **空间与骨架合规**：米制尺度正确、底面中心为 `(0, 0, 0)`；T5 角色严格符合 23(+3) 骨标准且包含 `root` 节点。
